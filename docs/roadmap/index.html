  • eba3a61 2026-08-20 Processing rule: Add raw payload absent → present
    absent -> present. Burp Payload Processing rule "Add raw payload": re-inserts the unmodified original payload at that point in the chain, most commonly used after a hash/encode step to build a sign-then-send value (hash+raw). The engine (intruder_rules.cpp) previously threaded only the running value through each rule with no notion of the untouched pre-chain original, so there was no way to get back to it once an earlier rule (e.g. sha256) had overwritten the running value. Added a third `original` parameter to applyRule (2-arg overload defaults it to value, so every existing call site and the 40+ existing unit tests are untouched) and have applyRules thread the constant pre-chain payload through as `original` on every step of the loop, so add-raw-payload appends the true original no matter where it sits in the chain or how many times it repeats. New op registered in operations() (auto-flows to the GUI dropdown via the existing /api/intruder/rule-ops -> ruleOps live-fetch, ui-v2/tabs.jsx:1642-1648) plus added to the static RULE_OPS_FALLBACK for when that fetch fails. 5 new unit tests in Tests/intruder_rules/intruder_rules_test.cpp lock the standalone self-append semantics, correct original-vs-running-value behavior after an earlier transform, the sha256-then-raw sign-then-send pattern named in the prior gap text, a repeated-in-chain case, and operations() advertisement. Backend C++ change this cloud session cannot build locally -- pushed and will be confirmed against a green GitHub Actions ctest run (ctest -R intruder_rules) before being called fully verified; documented here as the honest state at push time per this file's convention for cloud session C++ waves.

How this stays true

The data lives in docs/roadmap/parity.json and this page is generated from it by scripts/parity_report.py. When a commit closes a gap it updates that item's state and records the commit, then regenerates — and CI fails the build if the committed page has drifted from the data. The bar for calling something present is the same one the audit used: reachable by a real user, handling what Burp handles, verified by reading the code. An inflated roadmap would be worse than none, because it hides the work.
