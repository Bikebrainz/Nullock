Documentation

Self-host first. Everything here runs on your machine, offline, with no account.

Getting started

nullock is a man-in-the-middle proxy. It sits between your client and the network, captures every request and response, and lets you intercept, replay, and rewrite them. Three things to know before you start:

  1. It installs a local CA so it can read TLS. You control that CA; it never leaves your machine.
  2. History is a single SQLite file. Back it up, copy it, grep it — it's just a file.
  3. There is no telemetry. The binary makes no network calls except the traffic you point at it.

Install

Pick a platform. All builds are signed and reproducible from source.

terminal
# macOS
brew install nullock

# Linux (Debian / Ubuntu)
curl -L https://get.nullock.dev | sh

# From source — needs Rust 1.78+
cargo install --git https://github.com/nullock/cli

Trust the CA so TLS sites stop warning. nullock prints the exact path on first run:

terminal
nullock ca install
# [nul-] CA added to system trust store ✓

Your first capture

Start the proxy on a port and point your client at it. The desktop app does this with one click; from the CLI:

terminal
nullock --proxy :8080 --scope app.local
# [nul-] listening on :8080 — system proxy set
# [nul-] scope: app.local (3 hosts matched)
# ─── working ───

Everything matching --scope lands in the history table. Click a row to inspect the raw exchange, or hit r to send it to Repeater.

tip

Out of scope traffic is still proxied — it just won't clutter your history. Widen scope later without losing rows.

CLI

The desktop app is a front end over the same binary. Anything you do in the UI, you can script.

CommandWhat it does
nullock --proxy :PORTStart capturing on a port
nullock replay <id>Re-send a captured request
nullock export --jsonDump scoped history to JSON
nullock rules addAdd a match & replace rule
nullock ca installTrust the local CA
nullock vacuumCompact the SQLite history file

Extensions

Drop a single file into the extensions directory. It's loaded on next start — no build step, no marketplace gate. Hook the request lifecycle in JS or Python:

strip-tracking.js
// ~/.nullock/ext/strip-tracking.js
export function onRequest(req) {
  if (req.host.endsWith('telemetry.vendor.io'))
    req.block('blocked by ext');
  return req;
}

Available hooks: onRequest, onResponse, onConnect. Each gets a mutable object and returns it. Throw to drop the connection.

Security model

A MITM proxy is, by design, a tool that reads encrypted traffic. Here is exactly what nullock can and cannot see, and where the lines are:

  • The CA is yours. Generated locally on first run, stored in your OS keychain. We never ship a shared key. Delete it and interception stops.
  • Captures stay local. History is a file on disk. Nothing syncs unless you buy Hosted and opt in per scope.
  • Secrets in history. Tokens and cookies land in plaintext in your SQLite file — that's the point. Encrypt the disk; don't commit the file.
  • Reporting a flaw. Email security@nullock.dev with a PGP key on the site. We respond within 72 hours and credit you on the advisory.
warn

Only intercept traffic you own or are authorized to test. nullock is a tool; the law is yours to follow.
