Security model

Nullock by design handles untrusted bytes. This page is what we defend against, what we don't, and how to report a problem.

The canonical source is SECURITY.md in the repo. Highlights below.

Threat model

What we defend against (verified)

23 distinct attack surfaces -- documented in SECURITY.md. Headlines:

  • CSRF on every /api/* writer
  • DNS rebinding via Host validation
  • Path traversal in project / theme names
  • HAR import path validation + size cap
  • Session manager strips CR/LF/NUL from captured cookies
  • JS extension boundary validates every returned method/path/header/status
  • Hostname validation before openssl invocations
  • Match & Replace ReDoS via pattern pre-compile + 4 KB pattern cap
  • Match & Replace scope-gating (no rewrites of out-of-scope browsing)
  • Cross-engagement session leak fixed
  • HAR / Postman / Copy-as auto-redaction of 12 sensitive header names
  • NDJSON query-string suppression to prevent ?token=... exfil to log files
  • Upstream TLS peer verification + name pinning
  • CL+TE HTTP smuggling defence
  • Slowloris defence on the control server (absolute deadlines)
  • XXE / billion-laughs defence on nmap import
  • WebSocket buffer cap (per-stream)
  • /api/search ReDoS heuristic + body cap
  • Intercept toggle race fix
  • Project store I/O race fix (FD recycling)
  • QtConcurrent shutdown drain
  • Imported M&R rule quarantine
  • CA private key owner-only ACL

What we DON'T defend against

  • Local processes running as the same user. They can read your project files. We can't help that without OS-level sandboxing.
  • You installing a malicious extension. Extensions are explicitly trusted code; review before installing.
  • You writing a pathological M&R regex. Qt's PCRE doesn't expose a match-budget; we mitigate via pattern-size and shape heuristics but a deliberate (a+)+$ against a 100MB body will still spin CPU.
  • SChannel TLS-fingerprint shaping. We can reorder ciphers but not TLS extension order on Windows; documented as a v2 OpenSSL-direct item.
  • HTTP/3 / QUIC. Absent. Not on the v1 radar.

Reporting a vulnerability

Preferred path: GitHub Security Advisory at github.com/Bikebrainz/Nullock/security/advisories → Report a vulnerability.

What to include:

  • Affected version
  • OS
  • Repro steps -- shortest possible
  • Impact
  • PoC if available
