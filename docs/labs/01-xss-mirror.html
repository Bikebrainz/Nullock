01 Client-side Easy localhost:5001

Reflected XSS via search echo

The /search endpoint echoes the `q` query parameter back into the HTML response without escaping it. Classic reflected XSS.

start the lab
pip install flask
python labs/01-xss-mirror/app.py
# then open http://localhost:5001/
pre-set scope
http://localhost:5001/*http://127.0.0.1:5001/*

Hints

Stuck? Open these one at a time -- each reveals a bit more than the last.

Hint 1

Look at what happens to characters you type into the search box when they come back in the response.

Hint 2

Try sending an HTML tag as the search term and see if it survives unescaped.

Hint 3

A payload like <img src=x onerror=alert(1)> in the q parameter executes when Nullock replays the request.

Walkthrough

  1. nullock scope add http://localhost:5001/*
  2. Browse http://localhost:5001/search?q=hello
  3. Right-click the captured row -> Send to Repeater
  4. Change q to: <img src=x onerror=alert(1)>
  5. Fire. Inspect response body -- canary survives unescaped.
  6. Run the active probe on the row (probe button) and watch the passive scanner raise a "reflected-xss" finding.
  7. Confirm success: GET /flag?q=<img src=x onerror=alert(1)> -- the endpoint replays the same unsafe interpolation /search uses and hands back the flag once your payload survives unescaped.
the fix

The fix would be to render via jinja's autoescape or escape() the value before interpolation.

⚑

Every lab maps to a Nullock probe, so you learn the bug class and how to confirm it with the tool. The scope above is pre-set to the lab host, so active probes only ever fire at the lab — never at anything else you have open.
