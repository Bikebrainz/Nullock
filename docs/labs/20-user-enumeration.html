20 Authentication localhost:5020

Username enumeration via distinct login errors

/login returns "Unknown username" for a non-existent account but "Wrong password" for a real one -- so an attacker can enumerate valid usernames without ever logging in. In Nullock: 1. nullock scope add http://localhost:5020/* 2. Send /login to Intruder; fuzz the `user` field with a wordlist. 3. Filter responses: a "Wrong password" body means the user exists. Fix: return ONE generic message ("invalid username or password") for both cases, and keep response timing constant (hash even for unknown users).
