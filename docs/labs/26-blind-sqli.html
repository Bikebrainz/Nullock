26 Injection Medium localhost:5026

Blind (boolean-based) SQL injection

/product?id=... concatenates id into a SQLite query. There's no error output, but the response differs when the injected condition is true vs false ("in stock" vs "no such product"), so data leaks one bit at a time. In Nullock: 1. nullock scope add http://localhost:5026/* 2. Send /product?id=1 to Repeater. 3. id=1 AND 1=1 -> shown; id=1 AND 1=2 -> not shown (boolean oracle). 4. Automate with Intruder, e.g. id=1 AND substr((SELECT password FROM users LIMIT 1),1,1)='s' 5. Confirm success: GET /flag?password=<extracted password> -- solved only by submitting the actual admin password extracted bit by bit, never visible through the legitimate /product?id= path. Fix: use parameterized queries; never string-concatenate SQL.
